# Plantry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy Plantry — a shared household inventory PWA with low-stock alerts, auto-deduct, one-tap shopping lists, photos and barcode scanning — on the S2 homelab.

**Architecture:** pnpm TypeScript monorepo mirroring Velvet Scoop (`D:\code\Velvet Scoop\website-v2`): Fastify 5 + Prisma backend (thin routes over services, one `applyEvent` writer for all stock changes, in-process daily job), React/Vite/RTK Query PWA served by Caddy which proxies `/api/*`. All household data lives under `/api/households/:hid/*` behind a single membership-checking plugin. PostgreSQL only — sessions included; MinIO (Dinner Club's instance) for photos via presigned URLs.

**Tech Stack:** Node 20, pnpm 10, TypeScript 5.6, Fastify 5, Prisma 5.22, zod 3, openid-client 5, web-push 3, node-cron 3, @aws-sdk/client-s3 3, tsup, Vitest 2, React 18, react-router-dom 6, Redux Toolkit 2 (RTK Query), Tailwind 3, @radix-ui/react-dialog, vite-plugin-pwa, @zxing/browser, Playwright, Caddy 2.

**Spec:** `docs/superpowers/specs/2026-09-19-plantry-design.md` — read it before starting any task.

## Global Constraints

- Package scope `@plantry/*`; packages `@plantry/backend`, `@plantry/frontend`, `@plantry/shared`.
- API JSON is **camelCase**. Success responses are `{ "data": ... }`; errors are `{ "error": { "code", "message", "details"? } }`. HTTP 204 for bodiless successes.
- Error codes (exact strings): `validation_error` 400, `archive_first` 400, `unauthorized` 401, `forbidden` 403, `not_found` 404, `last_owner` 409, `unit_in_use` 409, `barcode_conflict` 409, `already_on_list` 409, `undo_expired` 409, `invite_invalid` 410, `rate_limited` 429, `photos_disabled` 503.
- Any resource id from another household, and any `:hid` the caller isn't a member of → **404 `not_found`**.
- Every household-data route registers inside the scoped plugin (`apps/backend/src/scoped/index.ts`). Never register one on the root app.
- `inventory_events` + `inventory.current_count` are written **only** by `services/inventory.ts` (`applyEvent` / `undoEvent`).
- Quantities: `Decimal(12,3)` in DB, plain JS `number` in JSON. Convert with `num()` from `src/lib/num.ts`.
- Rate windows are exactly `30d | 60d | 90d | 183d | 365d`.
- Cookies: session `plantry_sid` (HttpOnly, SameSite=Lax, Secure in prod, 7-day sliding); OIDC state `plantry_oidc`.
- Mutating requests (non-GET/HEAD/OPTIONS) must carry `Origin` equal to `FRONTEND_ORIGIN` → else 403 `forbidden`.
- Env names: `DATABASE_URL`, `SESSION_SECRET`, `SESSION_COOKIE_SECURE`, `FRONTEND_ORIGIN`, `AUTHENTIK_ISSUER_URL`, `AUTHENTIK_CLIENT_ID`, `AUTHENTIK_CLIENT_SECRET`, `AUTHENTIK_REDIRECT_URI`, `AUTHENTIK_ADMIN_GROUP` (default `plantry-admins`), `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `S3_ENDPOINT`, `S3_PUBLIC_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `GITHUB_FEEDBACK_TOKEN`, `GITHUB_FEEDBACK_REPO` (`owner/repo`), `AUTH_DEV_BYPASS`, `TZ`, `PORT`.
- Optional integrations are all-or-nothing and self-disabling: no `VAPID_*` → no push; no `S3_*` → photos 503 + UI hidden; no `GITHUB_FEEDBACK_*` → feedback routes absent + UI hidden. `/api/me` reports `pushEnabled`, `photosEnabled`, `feedbackEnabled`.
- Backend tests run against real PostgreSQL (`plantry_test` on `localhost:5434`), single-threaded; `resetDatabase()` in `beforeEach`. Test DB URL must end in `_test` or the setup file throws.
- Relative imports in `apps/backend` and `packages/shared` use `.js` extensions (NodeNext).
- TDD: write the failing test, watch it fail, implement, watch it pass, commit. One commit per task minimum. Commit trailer: `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.
- No Redis, no worker container, no offline mutation queue, no server-side image processing.
